## Current macOS build

The checked-in Xcode project currently points to `/Users/leemeredith/Documents/of_v0.12.1_osx_release`. If the SDK moves, update the project with the openFrameworks 0.12.1 project generator and the add-ons in `addons.make`. The generated project must include ARM's existing `src/main.cpp`; do not retain generator-created `src/ofApp.*` references. ARM's `Project.xcconfig` sets `MACOSX_DEPLOYMENT_TARGET = 12.0`; the stock Kinect example still has `11.5` in its configuration and Xcode 27 may request that it be raised to 12.0.

From the repository root:

```sh
xcodebuild \
  -project AugmentedRealityMirror.xcodeproj \
  -scheme "AugmentedRealityMirror Release" \
  -configuration Release \
  -derivedDataPath build/DerivedData \
  ARCHS=arm64 ONLY_ACTIVE_ARCH=YES \
  build
```

The output app is `bin/AugmentedRealityMirror.app`. The current build writes JSON in the generated record directories and no longer links Poco; its storage roundtrip test passes, and its live Kinect screen has been rerun. The bundled audio file remains in the data directory, but playback is disabled by default in `dataLoggerARM.cpp`. Keep code signing enabled: the generated project signs locally with the USB and camera entitlements in `of.entitlements`, like the stock Kinect example. An unsigned build made with `CODE_SIGNING_ALLOWED=NO` lacked those entitlements.

For a build against an already compiled openFrameworks SDK in a restricted workspace, add `OF_CORE_BUILD_COMMAND=/usr/bin/true` to the `xcodebuild` command. This skips only the SDK core rebuild; it still compiles and links ARM. The September 22 JSON Release build passed this way using the existing SDK library.

## Legacy record conversion

ARM now loads `.json` records and interface messages. The bundled message presets were converted in the repository. To retain locally generated flythrough and session records from the XML version, run this from the repository root:

```sh
python3 scripts/migrate_xml_to_json.py bin/data/record/address/flythrough bin/data/record/address/session
```

The converter creates a JSON file beside each XML file and skips an existing JSON destination. It leaves the XML originals intact as backups. `DemoMe.xml` becomes `DemoMe.json`; `DemoMeSessions.xml` becomes `DemoMeSessions.json`. Generated records in `bin/data/record/address/` are ignored by Git and must not be committed with participant data. The current app does not load XML.

The storage test can be run without a Kinect:

```sh
clang++ -std=c++23 -I /path/to/of_v0.12.1_osx_release/libs/json/include \
  tests/arm_json_document.cpp -o /tmp/arm_json_document_test
/tmp/arm_json_document_test
python3 -m unittest discover -s tests -p 'test_*.py'
```

The Xcode project was generated by openFrameworks 0.12.1. Its generator initially added WebAssembly OpenCV libraries to the macOS link settings; those entries were removed from the checked-in project. If the project is regenerated, confirm the macOS target links only the macOS OpenCV archive before building.

## Kinect verification procedure

1. Confirm the Kinect's external power supply and USB data connection are both seated. Check the USB device listing before launching an app. On September 21, 2026, `ioreg -p IOUSB -l -w0` initially showed only Microsoft product `0x02b0` (`Xbox NUI Motor`, decimal 688). It later showed the audio and camera components as well, including camera product `0x02ae` (decimal 686).
2. Run the openFrameworks 0.12.1 `examples/computer_vision/kinectExample` by itself. Confirm a stable color/depth feed for several minutes and record the exact model number printed on the Kinect. After a fresh connection, the example displayed a point cloud for several minutes despite one `[Stream 70] Expected 1748 data bytes, but got 948` message. Separate command-line runs of both the example and ARM sometimes logged missing depth/color data and repeatedly reconnected. One short-packet warning alone does not establish failed capture; a sustained feed is the useful check. A ten-second reconnection interval did not resolve the failing run and was reverted.
3. Quit the example before launching ARM; only one process can own the USB camera. An earlier ARM process left running by a separate foreground launch held `UsbExclusiveOwner` even after its terminal session ended, and a new ARM process launched from Xcode failed with `LIBUSB_ERROR_ACCESS`. After stopping the stale process, Xcode-launched ARM opened the camera but still entered the missing-stream reconnect loop. Check `ioreg -p IOUSB -l -w0` for `UsbExclusiveOwner` if access errors recur, and power-cycle the Kinect if it remains stuck after failed opens.
4. Open `AugmentedRealityMirror.xcodeproj` in Xcode, select the `AugmentedRealityMirror Debug` scheme, and click Run. ARM now starts on the Kinect screen. A black screen can appear briefly while `ofxKinect` performs its startup retry. If it remains black, press `o` once to close and reopen device index 0. Pressing `c` closes the connection. On September 24, 2026, a clean launch recovered automatically and a separate `c`/`o` cycle restored the live feed.
5. Complete the sensor-dependent checks below. Record the exact model, power supply, USB adapter, connection procedure, and any macOS permissions here.
